# 能力模型

| 项 | 内容 |
| --- | --- |
| 版本 | 草案 0.1 |
| 日期 | 2026-11-14 |

能力是 WaiShe 中功能的最小单位。驱动声明设备有哪些能力，Bridge 据此调度读取和校验写入，Dashboard 据此生成界面。三者之间不传递“这是哪个型号”之类的判断。

## 1. 能力描述

驱动为每个设备返回一组能力描述，每项包含：

| 字段 | 说明 |
| --- | --- |
| 标识 | 形如 `域.名称`，例如 `battery.level` |
| 访问方式 | 读、写、通知的任意组合。读和写分别声明，一个设备可以只读某项能力 |
| 值类型 | 见第 3 节 |
| 约束 | 仅可写能力需要：数值范围与步进，或可选值列表。约束针对当前端点，同一设备有线与无线下可以不同 |
| 持久性 | 仅可写能力需要：`onboard` 写入设备板载存储 / `volatile` 断电或重连后丢失 / `unknown` |
| 建议轮询间隔 | 仅可读且无通知的能力需要。Bridge 可以放慢，不会比它更快 |
| 精度 | 仅电量需要：`exact` 精确百分比 / `steps` 档位，附档数 |

验证等级不由驱动代码返回，而是记录在驱动的设备表中并由 Registry 展示，见 `docs/driver-interface.md`。

## 2. 标准能力目录 0.1

### 首期（P0）

| 标识 | 值类型 | 访问 | 说明 |
| --- | --- | --- | --- |
| `battery.level` | 百分比 | 读，可通知 | 0 至 100。读不到时返回不可用，不得返回 0 |
| `battery.charging` | 枚举：`discharging`、`charging`、`full` | 读，可通知 | |
| `link.state` | 枚举：`connected`、`asleep`、`disconnected` | 读，可通知 | 设备相对于当前端点的链路状态。接收器在线而设备关机时为 `disconnected` |
| `device.firmware` | 文本 | 读 | 用于兼容记录与问题报告 |
| `mouse.dpi` | DPI：X 与 Y 两个整数 | 读、写 | 约束为范围与步进，并声明 X/Y 是否可独立设置 |
| `mouse.polling_rate` | 整数，单位 Hz | 读、写 | 约束为可选值列表 |
| `headset.mic_mute` | 布尔 | 读、通知；写可选 | 首期只要求读与通知。能否写取决于协议，单独声明 |

### 规划中（P1，标识与类型未定稿）

`mouse.dpi_stages`、`mouse.profile`、`headset.volume`、`headset.mic_volume`、`headset.sidetone`、键盘相关能力。

## 3. 值类型

| 类型 | 表示 | 通用控件 |
| --- | --- | --- |
| 百分比 | 0 至 100 的整数 | 进度条 |
| 布尔 | 真 / 假 | 开关 |
| 整数 | 带单位的整数 | 约束为范围时用滑块，为可选值列表时用选择器 |
| 枚举 | 一组预定义的标识 | 选择器 |
| 文本 | 字符串 | 只读文本 |
| DPI | X、Y 两个整数 | 专用控件 |

Dashboard 对认识的能力使用专用控件，对不认识的能力按值类型和约束使用通用控件。因此新增一项使用已有值类型的能力时，Dashboard 不需要改动。

## 4. 读数状态

每次读取的结果是以下之一：

| 状态 | 由谁给出 | 含义 |
| --- | --- | --- |
| `ok` | 驱动 | 读取成功 |
| `unsupported` | 驱动 | 该设备或当前端点没有此能力。通常表现为能力清单里没有这一项 |
| `unavailable` | 驱动 | 有此能力但现在读不到。原因：`asleep`、`disconnected`、`busy`、`timeout`、`protocol` |
| `unknown` | Bridge | 尚未读取过 |

历史值标记由 Bridge 根据读取时间和端点状态判定，驱动不参与。

**驱动的义务**：区分“设备应答了一个值”和“接收器替不在线的设备应答”。后者必须返回 `unavailable`，不得返回 0 或上一次的值。

## 5. 写入结果

| 结果 | 含义 |
| --- | --- |
| `applied` | 已写入并经回读确认 |
| `accepted` | 设备确认收到，但协议无法回读 |
| `rejected` | 参数非法或不支持 |
| `failed` | 通信错误或超时，设备状态不确定 |

驱动在协议允许时必须回读。另有一种中间结果“等待重新枚举”：驱动告知这次写入会使设备重新枚举，Bridge 负责等待端点重新出现并发起回读。

## 6. 新增能力

1. 在 `waishe` 仓库开 Issue 说明用途、值类型、约束，并列出至少两个不同品牌的设备如何映射到它。只对应单一品牌的功能不进入标准目录。
2. 向本仓库提交对能力目录的修改。
3. 若需要专用控件，再向 `waishe` 仓库提交 Dashboard 的修改；否则通用控件即可工作。

命名规则：小写，`域.名称`，名称内用下划线；域按设备类别或通用功能划分（`battery`、`link`、`device`、`mouse`、`headset`、`keyboard`）；单位不写进名称。
